# Tardi Tetris: how it is built and why

`games/tetris`. Two to four players, one well each on the TV, phones as
controllers. Clearing two or more rows at once buries every opponent in garbage.
Last well standing wins.

---

## Files

```
game.json                    title, description, 2 to 4 players
package.json                 build / dev / test / test:mutate
.prettierrc                  single quotes, no semicolons, 90 cols
assets/thumbnail.png         512x512, generated by script (see platform-contract.md)
src/
  table.js                   TV entry point: owns the simulation and the clock
  hand.js                    phone entry point: a controller, holds no state
  table-view.js              draws the row of wells, sizes them, diffs repaints
  hand-view.js               draws the control pad, handles press-and-repeat
  shared/
    tetris-rules.js          pure rules: no DOM, no timers, fully unit-tested
    skin.js                  the stylesheet, next-piece preview, lineCount()
test/
  rules.test.mjs             33 headless tests
  mutate.mjs                 breaks the rules on purpose, 11 mutations
```

The split that matters: **`shared/tetris-rules.js` is pure**. No DOM, no timers,
no platform. That is what makes the game logic provable headlessly in Node, and
it is where new game logic belongs. Everything that touches the screen lives in
the two `*-view.js` files.

## Why the Hand holds nothing

The platform may drop Table-to-Hand messages and only guarantees the most recent
one. So the Hand renders no board, no piece, no falling anything. It shows the
player's own line count and next piece, both of which change **only when a piece
locks**, so a dropped message costs nothing and self-corrects on the next lock.

Everything else is on the Table: gravity, collision, rotation, line clears,
garbage, and the win check. A button press travels Hand to Table, which is the
direction with the strong ordering guarantee.

This is also why 12 rapid presses land as 12 moves in order rather than being
coalesced or lost.

## Message shapes

Hand to Table is a bare string action: `'left'`, `'right'`, `'rotate'`,
`'soft'`, `'drop'`.

Table to Hand is a scoreboard, never a board:

```js
{
  phase: 'waiting' | 'countdown' | 'playing' | 'over',
  countdown: 3,
  victorId: null,
  players: [{ playerId, nick, lines, level, alive, next }]
}
```

Each Hand finds itself in `players` by its own `playerId`.

**Broadcasts are throttled** to at most one per 250ms (`BROADCAST_MS`), and only
sent when something meaningful changed (`dirty`). A 50ms simulation tick
broadcasting every frame would flood the platform for no benefit, since a Hand
that misses one is guaranteed the next.

## Game rules as implemented

- 10x20 well per player. Standard 7 tetrominoes.
- **7-bag randomiser:** every 7 pieces contains each shape exactly once, so a
  player is never starved of the piece they are stacking for.
- **Rotation** turns the piece inside its own square box, with wall kicks tried
  at offsets `[0, -1, 1, -2, 2]`. Kicks matter because only *cells* are collision
  checked, never the box, so a piece whose box has an empty column can sit with
  that column off the board; rotating there swings a cell into the wall.
- **Attack table** by rows cleared at once: `[0, 0, 1, 2, 4]`. One row sends
  nothing. That is what makes stacking for a tetris worth the risk.
- **Garbage** rises from the bottom. Every row in one batch shares the same hole
  column, so it stays diggable. If it pushes a block through the ceiling, that
  player is out.
- **Top out** happens two ways: a piece locks with any cell above the ceiling, or
  a new piece has no room to spawn.
- **Gravity** is `800 - level * 65` ms per row, floored at 120ms so the game
  stays playable over a network rather than becoming a reflex test.
- Pieces spawn above the ceiling (`y` of -1, or -2 for the I piece) so a full row
  can still land.
- A player joining mid-match gets a live well and joins the fight.

## Rendering, and why it is written oddly

**Repaints are diffed.** 200 cells per well times four wells is 800 elements.
Each cell caches the colour it was last painted and only changed cells are
touched. The cache is a JS array, not a read of `style.backgroundColor`, because
the browser normalises `'#22d3ee'` to `'rgb(34, 211, 238)'` so reading it back
never matches what you wrote and every cell would repaint every frame.

**Wells are sized in pixels from JS.** A 2018 TV browser has no `aspect-ratio`,
so holding 10x20 is arithmetic, not CSS.

**The size is measured, not predicted.** `layout()` picks a cell size, applies
it, then measures the tallest rendered well and shrinks until it fits, up to 8
times. The first version guessed the height of each well's name, score and
preview with a `vmin(9)` constant. That guess was too small, so the wells
overflowed their row and rode up over the title. Do not reintroduce a predicted
chrome height: fonts are in `vmin` and the preview scales with the cell, so the
only honest answer is to measure.

**The landing shadow** is the piece's colour mixed most of the way toward the
empty-cell colour, so it reads as a hint and never as a real block. It is painted
before the piece so the piece covers it when they overlap.

## The control pad

Five buttons: rotate, hard drop, left, soft drop, right. Left, right and soft
drop **repeat while held** (200ms delay, then every 60ms), because tapping once
per cell is not a way to play tetris.

- Both `touchstart` and `mousedown` fire `press`, and `press` calls
  `preventDefault()`. Without it a tap fires the mouse event afterwards too and
  the piece jumps two cells.
- Arrow keys and space are wired for the dev harness on a laptop. Nobody plays
  that way in a living room, but it makes manual testing possible.
- Buttons are disabled unless the match is playing and this player is alive.
- Minimum 44px tap targets, enforced in CSS and asserted in the browser checks.

## Text

Use `lineCount(n)` from `shared/skin.js` for anything showing a line total. It
returns "1 line" and "2 lines". Players read this every round.

Render nicks, never `playerId`. The scoreboard, the winner headline and each
well's label all use the nick the platform supplies.
